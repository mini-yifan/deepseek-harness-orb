# Agent Note: Experimental Computer Use plugin

Status: implemented

English | [中文](2026-09-13-experimental-computer-use.zh.md)

## Problem

A vision model can already consume image blocks that a tool result or user message carries, but the shipped agent-loop has no host plugin that captures the live desktop, maps a 0–1000 coordinate space onto displays, and posts GUI input. Putting that behavior in a Skill would hide it from the tool catalog. Changing `agent-loop` to special-case screenshots would make visual desktop control a loop feature instead of a composition choice. An observe/screenshot tool would spend a turn on a capture the next GUI action must repeat anyway.

## Decision

`@deepseek-ai/dsh-experimental-tool-computer-use` is a private experimental Cordis plugin. It registers thirteen exclusive GUI tools (`click`, `input_text`, `scroll`, `hotkey`, `wait`, `long_wait`, `screenshot`, `long_press`, `drag`, `open_in_browser`, `open_in_finder`, `list_apps`, `open_app`) and attaches the current frontmost window on the first user turn through `agent/pre-step`. Each tool performs one desktop action, waits `postActionWaitMs` immediately before recapture pixels, and returns `[text envelope, ...ImageBlock]` from `output.render`. The envelope starts with `<frontmost_app>` (plus `<frontmost_window>` when the window has a title, `<frontmost_folder>` when Finder is frontmost, or `<focus_note>` when nothing remains after skipping overlay windows), then `<screen_index>0</screen_index>` and `<coordinate_space>0-1000</coordinate_space>` when a window was captured; [Computer Use observation foreground](2026-09-15-computer-use-observation-foreground.md) owns those foreground tags, [Computer Use focused-window observation](2026-09-16-computer-use-focused-window-observation.md) owns the owner pick and `list_apps` / `open_app`, [Computer Use app-window observation](2026-09-16-computer-use-app-window-observation.md) owns the family union and always-region capture, and [Computer Use 0–1000 fraction coordinates](../bug-fix/2026-09-15-computer-use-fraction-coordinates.md) owns the click space. Images live in content, not `presentationMeta`. There is no observe tool. `screenshot` writes Desktop files and the clipboard; [Computer Use screenshot export](2026-09-15-computer-use-screenshot.md) owns that export. [Computer Use pointer and open tools](2026-09-15-computer-use-pointer-and-open-tools.md) owns `long_press`, `drag`, `open_in_browser`, and `open_in_finder`. [Computer Use wait and long_wait](2026-09-15-computer-use-wait-and-long-wait.md) owns the two wait tools.

`applyComputerUse(ctx, backend, config)` is the shared registration helper. Production `apply` uses the host-platform backend (macOS capture and HID input; other platforms throw the fixed macOS-only error at execute). Tests and keyless snapshots inject a fake desktop that returns a fixture PNG and records actions. There is no Config `driver: fake`. macOS HID posting is owned by [Computer Use macOS HID](../bug-fix/2026-09-13-computer-use-macos-hid.md).

The plugin injects `tools`, `systemPrompt`, and `attachments`. Missing attachments keep it pending. Optional `llm` gates image-capable routes: text-only routes skip first-frame images and refuse the tools. Installing or patching the plugin is the consent gate; tools do not `ask` per click. The plugin is not in `dsh-base`. Local try is `pnpm dsh web --patch packages/experimental/tool-computer-use/cordis.source.patch.yml`, then a new session on the Computer Use agent preset. Desktop copies the same package as a signed runtime extra and mounts the locator from Desktop Host, not as an npm dependency; see [Desktop floating orb](2026-09-14-desktop-floating-orb.md).

The Web overlay inserts only `computer-use-preset-root`, which provides the extra `trust: system` agent-presets root next to this package. The overlay adds `inject: [computerUsePresetRoot]` on the `agent-presets` row so Loader interpolation of `!!js ctx.computerUsePresetRoot` waits for that service. GUI tools register in that preset's standing scope. The Host catalog and the shipped `standard` preset do not receive them. The Computer Use preset also registers `code_agent`, which creates or continues a first-class standard Session through `session.create` / `session.prompt` so the desktop sidebar can show the delegated work. After accept, a caller-owned watch parks a plugin notice until both sessions are idle; [Computer Use parks Code agent completion](2026-09-15-computer-use-code-agent-completion.md) owns that delivery. [Overlay Computer Use background dispatch](2026-09-17-orb-code-agent-dispatch.md) owns create cwd, the caller-owned registry, `code_agent_status` / `code_agent_stop`, and unattended Code-agent answerers.

Grounding copy is a `systemPrompt.section`. Coordinates are 0–1000 fractions of the visible screenshot; [Computer Use 0–1000 fraction coordinates](../bug-fix/2026-09-15-computer-use-fraction-coordinates.md) owns that contract. System screenshot chords (Cmd/Win+Shift+3/4/5) are rejected.

## Alternatives considered

**Skill-only grounding.** A Skill can carry See/Step copy, but it cannot register tools, attach durable images, or appear in the generated tool catalog. Computer Use is a Cordis plugin with a prompt section, composed from the Computer Use agent preset.

**Host-insert the GUI tools.** Host-registered tools appear in every preset, including `standard`. The overlay adds a system extra root instead, so only sessions that name `computer-use` receive the thirteen GUI tools.

**Change `agent-loop`.** The loop already forwards tool-result images into the next request. A loop special case would make desktop control a core semantic and force every composition to know about screens.

**Observe tool.** A dedicated capture tool would add a turn whose only job is an image the next GUI tool must recapture after acting. Observation belongs in the first user turn and in every GUI result. Saving a user-visible file is a different action, owned by [Computer Use screenshot export](2026-09-15-computer-use-screenshot.md).

**Per-click `ask`.** The interaction seam's `allowed-once` grant cannot keep a visual loop usable. Consent is installing or patching this experimental plugin; the README states that it drives the real unsandboxed desktop.

**Capability seam in this cut.** One package owns the macOS backend, tools, and pre-step. A second backend (Playwright / Electron) would justify splitting Service Definition from Provider.

**Windows/Linux input in this cut.** Non-macOS hosts still load so Linux CI can mount a fake backend. Production methods throw at execute.

**`tool-subagent` for background coding.** `origin: 'subagent'` hides the child from the workspace sidebar and `session.prompt` rejects it. `code_agent` uses the same Host create/prompt path as a user-typed standard session.

## Consequences

Mounting the plugin on an image-capable route in the Computer Use preset adds policy tokens and thirteen exclusive GUI schemas plus `code_agent`, `code_agent_status`, and `code_agent_stop` on every request, plus image tokens for first-frame notices and every GUI result until compaction. Text-only routes keep coding sessions working: first-frame attachment is skipped and GUI tools fail with a route diagnostic. macOS needs Screen Recording and Accessibility; missing rights fail capture or input with a named TCC message. `input_text` overwrites the string clipboard during paste and restores it afterwards. The attached screenshot is the overlay-skipped frontmost application, not a display panorama; [Computer Use focused-window observation](2026-09-16-computer-use-focused-window-observation.md) owns the owner pick, [Computer Use app-window observation](2026-09-16-computer-use-app-window-observation.md) owns the family union and always-region capture, and [Computer Use transient window observation](2026-09-16-computer-use-transient-window-observation.md) owns the region helper. Desktop's main window stays capturable when it is next after overlay skip; the macOS overlay is omitted from Computer Use screenshots by ScreenCaptureKit window exclusion and is click-through only for the matching HID burst. Observation text also carries overlay-skip foreground tags owned by [Computer Use observation foreground](2026-09-15-computer-use-observation-foreground.md). There is no per-click approval, pixel-diff settle, lasso, or `dsh-base` default.

## Testing

Package tests use a fake desktop only. They cover coordinate mapping, hotkey rejection, tool execute/render, first-frame pre-step, text-only refusal, HMR, Loader composition through a test-only `cordis.yml`, an in-process agent-loop click that places image blocks on `user/message` and `tool/result`, the overlay-only preset-root locator, overlay YAML (no Host GUI insert, `agent-presets` injects `computerUsePresetRoot`), Loader interpolation of `!!js ctx.computerUsePresetRoot` after that inject, `scanRoot` of the extra preset, scoped GUI tools that stay absent from Host `schemas()`, `code_agent` create/continue/reject paths that append the same `user/message` events a sidebar session would receive, and parked `code_agent` completion notices that `followup` only after both sessions are idle. Injected macOS `CommandRunner` tests assert generated JXA contains `clickAt`, `pasteText`, `chord`, `CGEventCreateScrollWheelEvent2`, `longPressAt`, and `dragFromTo`, `/usr/bin/open` argv for browser and Finder, helper `--region=` argv when overlay window ids are set, and no `screencapture` fallback.

The authored headless overlay [`snapshots/session/computer-use/`](../../../../snapshots/session/computer-use/) mounts a scenario-local fake-desktop plugin plus vision model `deepseek-v4-flash-vision-exp` with `postActionWaitMs: 0`. Replay uses a fixture PNG and never drives a real desktop. The overlay stubs `sessionController` and registers `code_agent` so the header pin includes the `code_agent*` schemas; headless has no Session Remote. First-frame and the click result include `<frontmost_app>Pages</frontmost_app>`. The plugin is not in shipped `dsh-base`.
