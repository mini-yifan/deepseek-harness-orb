# Agent Note: Desktop overlay-guard IPC

Status: implemented

English | [中文](2026-09-14-desktop-overlay-guard.zh.md)

## Problem

Computer Use capture and HID run in the Desktop Host child. The macOS floating overlay is an always-on-top Electron panel (ball and expanded transcript share that window). Standing `contentProtection` on both Desktop windows hid the Harness UI from the agent and also hid the ball from every other capture. Standing click-through would steal the user's input box. Host Node IPC accepted only `ready` / `fatal` / `shutdown`; an unknown event killed the child. Overlay renderer IPC cannot see Computer Use sessions started from the main window. `/usr/sbin/screencapture` on macOS 15.4+ uses ScreenCaptureKit, which ignores `NSWindowSharingNone` (`contentProtection`), so a capture-time protection bit cannot omit the overlay from the framebuffer.

## Decision

Desktop Host protocol version is 8. Pipe `FRAME_MAGIC` stays `0x44534833` because the byte-pipe layout did not change. Node IPC carries ack'd `overlay-guard` (`begin` | `end`, `mode: capture` | `input`) with `overlay-guard-ack` `excludeWindowIds`, ack'd `observation-frame` (`bounds` or `null`) with `observation-frame-ack`, and ack'd `sck-capture` (`region`, `excludeWindowIds`, `output`) with `sck-capture-ack` (`error` on failure). Electron applies HID click-through when `mode` is `input`, waits `OVERLAY_GUARD_INPUT_APPLY_MS` (80) so WindowServer commits hit-testing, then acks even when no overlay exists (`excludeWindowIds: []`). On capture begin it reports CGWindowIDs for visible overlay windows (the floating ball, the selection toolbar only while shown, and the observation-frame ribbon only while shown). Hidden overlay windows are omitted: ScreenCaptureKit `onScreenWindowsOnly` cannot see them, and a missing exclude id fails capture. After HID returns, Host waits `OVERLAY_GUARD_INPUT_DRAIN_MS` (80) then `finally` always sends `end` for the outermost input interval. Nested `withInput` shares that input interval. Nested `withCapture` inside `withCapture` shares the outer capture exclude ids. Nested `withCapture` inside `withInput` still sends capture begin/end so exclude ids refresh after `setObservationFrame` shows the ribbon, without toggling click-through. Electron restores overlay chrome and hides the observation frame on Host exit. The overlay-guard ack wait is `OVERLAY_GUARD_ACK_TIMEOUT_MS` (1000). Overlay-exclude capture waits `SCK_CAPTURE_ACK_TIMEOUT_MS` (30000) because a Screen Recording prompt can appear. [Computer Use observation-frame ribbon](../feature/2026-09-19-computer-use-observation-frame.md) owns the ribbon. [Desktop ScreenCaptureKit in the Orb process](2026-09-20-desktop-sck-in-process-identity.md) owns why capture runs in Electron.

The main window never sets `contentProtection` or `ignoreMouseEvents`. The overlay stays drawn and hittable by default. Capture does not set `contentProtection`. `input` mode sets `setIgnoreMouseEvents(true, { forward: false })` and `blur()` on the whole overlay window only when the input count crosses from 0 to 1, and hides the selection toolbar instead of a second click-through window. Nested capture IPC while input is held does not blur again. HID tools and `open_app` hold that input cloak through recapture via `withGuiTurn`; [Computer Use context-menu observation](../bug-fix/2026-09-16-computer-use-context-menu-observation.md) owns that turn.

When `excludeWindowIds` is non-empty and the overlay-guard provides `captureExcludedRegion`, Computer Use capture sends `sck-capture` so ScreenCaptureKit runs in the Electron process. Hosts that omit that method spawn the Darwin `macos-sck-capture` helper. A missing overlay window in shareable content fails the capture; it does not fall back to `screencapture`. CLI and other hosts with an empty id list keep `screencapture`. [Computer Use app-window observation](../feature/2026-09-16-computer-use-app-window-observation.md) owns always-region observation capture. [Computer Use transient window observation](../feature/2026-09-16-computer-use-transient-window-observation.md) owns `--region=` and display `excludingWindows` plus crop. The helper and the in-process library still implement `--window=` / `SCContentFilter(desktopIndependentWindow:)`; observation does not call it.

Computer Use stays Electron-agnostic: `wrapDesktopBackend` wraps `listScreens`, `capture`, and inspect in `withCapture` (ids stored for the macOS backend) and HID plus `openApp` plus `withGuiTurn` in `withInput`; after `listScreens` it waits for `setObservationFrame`. `listApps`, `openInBrowser`, and `openInFinder` are unwrapped. [Computer Use focused-window observation](../feature/2026-09-16-computer-use-focused-window-observation.md) owns wrapping `listScreens`. Production `apply` uses `ctx.get('computerUseOverlayGuard')` and skips the wrap when the service is absent. Desktop copies the built `lib/index.js` extra and refuses a bundle that lacks that wrap. `start:desktop --skip-build` still rebuilds Desktop Host, the Electron shell, and this experimental package so `withCapture` cannot call `run()` without window ids. Desktop Host overlay YAML inserts `computer-use-overlay-guard`, which provides that service and must not import the experimental package. Only Computer Use declaration-merges the optional Context key, so the Host typecheck does not collide two `ComputerUseOverlayGuard` types. Index and the YAML plugin share one overlay-guard module instance so pending acks are not split across bundles. See [Desktop floating orb](../feature/2026-09-14-desktop-floating-orb.md).

## Alternatives considered

**Standing `contentProtection` on both windows.** That hid the Harness UI from the agent and hid the ball from user screenshots and meeting capture at all times.

**Hide or fade the overlay during capture.** The user would see the ball flash away.

**Capture-interval `contentProtection` only.** ScreenCaptureKit display capture on macOS 15.4+ still includes the window, and a protected window can vanish from `SCShareableContent.windows` so it cannot be excluded by id.

**Private `CGSSetWindowCaptureExcludeShape`.** That would keep `/usr/sbin/screencapture` but is not a public API.

**Overlay renderer IPC.** Computer Use on the main window would not cloak the ball.

**Host-initiated Fetch pipes.** Pipes are Electron-initiated Fetch only. Node IPC already carries control messages. Screenshot bytes do not fit the overlay-guard ack.

**Wrapping every `plugin.ts` execute.** First-frame capture is `agent/pre-step` and is not HID. HID tools hold input cloak through recapture with `withGuiTurn` under [Computer Use context-menu observation](../bug-fix/2026-09-16-computer-use-context-menu-observation.md).

## Consequences

Mixed Electron/Host shells fail at `ready` instead of on the first cloak. A lost `end` is recovered when the Host child exits. Concurrent Computer Use sessions share overlay refcounts. Keyboard focus can still land in the overlay outside an `input` interval; `open_app` and HID use `withInput` so the overlay blurs before activate or posted events. Web and CLI Computer Use stay uncloaked. Darwin Desktop extra copies include `lib/macos-sck-capture` when that helper was compiled. Packaged Electron unpacks `lib/macos-sck-napi.node` and `lib/libmacos-sck-capture.dylib` beside `macos-selection-napi.node`, not under `signIgnore` `dsh/`.

## Testing

Electron tests pin default `contentProtection === false` during capture begin, visible overlay `getMediaSourceId` window ids on capture ack (hidden toolbar and hidden observation frame omitted), input begin `ignoreMouseEvents({ forward: false })` plus hiding the toolbar, observation-frame show/hide plus always click-through, no extra blur for nested capture while input is held, async overlay-guard callbacks that ack only after the promise resolves, Host-stop restore including hiding the observation frame, overlay-guard, observation-frame, and sck-capture IPC that is not fatal (sck-capture failures ack an error string), and protocol 4 ready rejection. Desktop Host tests pin overlay YAML insert, pass-through without a sender, begin ack window ids reaching `withCapture`, throw restore, abort restore, ack timeout, `withInput` drain before `end`, nested `withInput` plus `withCapture` refreshing capture exclude ids, nested `withCapture` as one capture begin/end, observation-frame send/ack/timeout/abort, sck-capture send/ack/failure/timeout/abort, and `apply` plus installed transport. Computer Use tests pin `wrapDesktopBackend` capture vs HID vs cloaked `listScreens` and `openApp` vs unwrapped `listApps` / `openInBrowser` / `openInFinder`, `setObservationFrame` after `listScreens`, `turn/end` clear, `withGuiTurn` nested inside `withInput`, forwarded exclude ids, restore on throw, `apply` wrapping on a child context, helper `--region=` argv when ids are set and `captureExcludedRegion` is omitted, IPC capture when that method is provided, no `screencapture` fallback, CLI `setActivationPolicy(.prohibited)` vs library entry that does not change activation policy, and extra copy rejection without wrap.
